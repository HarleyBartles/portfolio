# Consuming tokens

## In CSS

Use `theme(--<token>)` to read a token value. The `theme()` function resolves the CSS custom property generated by the `@theme` block.

```css
.card {
  background-color: theme(--color-surface-primary);
  color: theme(--color-text-primary);
  padding: theme(--space-4);
  border-radius: theme(--radius-md);
  box-shadow: theme(--shadow-card);
  transition: background-color theme(--duration-200) theme(--ease-out);
}
```

If the build does not support `theme()` in a custom property context, fall back to `var(--<token>)` after confirming the custom property exists.

```css
.card {
  background-color: var(--color-surface-primary);
}
```

## In JSX and Tailwind utility classes

Use the Tailwind utility that maps to the token. Do not use arbitrary values.

```jsx
<div className="bg-surface-primary text-text-primary p-4 rounded-md shadow-card">
```

Allowed patterns:

- `bg-<token-name-without-prefix>` for `color-surface-*` tokens.
- `text-<token-name-without-prefix>` for `color-text-*` tokens.
- `p-<scale>`, `m-<scale>`, `gap-<scale>` for `space-*` tokens.
- `rounded-<scale>` for `radius-*` tokens.
- `shadow-<name>` for `shadow-*` tokens.
- `z-<name>` for `z-*` tokens.

The doubled `text-` in a utility such as `text-text-primary` is the correct, intentional form for the `color-text-primary` token: `text-` is the Tailwind text-color utility prefix and `text` is the token's group segment.

## Forbidden patterns

- Arbitrary values: `w-[37px]`, `text-[#333]`, `p-[1.25rem]`.
- One-off `!important`: `!p-4`, `!text-accent-primary`.
- Mixing raw values and tokens in the same component: `style={{ color: '#333' }}` alongside `className="text-text-primary"`.
- Using `rgb()`, `hsl()`, or hex values directly in component code.
