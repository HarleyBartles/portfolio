# Avoiding copying

Use this reference when a proposed design reference risks becoming a clone of the source.

## Red flags

A reference is likely a copy, not a principle, when you see:

- The same layout, colour pair, or typeface is repeated across many recent portfolio or Dribbble shots.
- Placeholder text, fake company names, or stock imagery that does not come from the reference's actual work.
- More decoration than content: effects such as glassmorphism, bento grids, or scroll reveals used without a reason.
- No variation across pages or sections; every page looks like a template.
- Accessibility or performance is clearly treated as optional.
- The reference's only justification is that it is "clean", "modern", or "aesthetic".

## How to synthesize

Synthesize means producing a new pattern that is informed by the reference, not matching it.

- **Change one variable.** Alter the typeface, scale, colour role, spacing, or motion easing so the output cannot be traced to the source.
- **Combine two references.** Take a layout principle from one reference and a colour principle from another, then adapt both to the portfolio voice.
- **Anchor it to real content.** Replace the reference's placeholder text and images with the portfolio's actual projects, skills, and writing.
- **Cross-check the voice.** Compare the result to [designing-premium-sites](../designing-premium-sites/SKILL.md). If it sounds like the source, not the portfolio, iterate.
- **Test with a second page.** A copied pattern works only on the hero; a synthesized pattern works across pages.

## Stock-look checklist

- [ ] The assets are original, licensed, or clearly generated for the portfolio.
- [ ] The text describes real work, not generic capabilities.
- [ ] The layout does not match a widely used template.
- [ ] The effects support the content, not the other way around.
- [ ] A user could not guess the original Dribbble shot or repo from the result.
