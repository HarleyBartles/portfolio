# Asset custody

## Use when

- You are adding a font, image, icon, or any other visual asset to the repository.
- You are deciding whether to self-host, use a CDN, or generate an asset with an MCP tool.
- You are optimizing, resizing, or converting an asset before it is used.
- You are reviewing an existing asset for source, license, format, or attribution.
- You are removing an asset and need to avoid orphan references.

## Core thesis

Assets are a custody problem, not a decoration problem. Before an asset enters the tree, you must know its source, its license, its file format, and the fallback that keeps the page usable when the asset fails. A missing source or an incompatible license is more expensive to fix later than a wrong colour. Record these facts in the asset custody for the project.

## Fonts

Treat every typeface as a licensed dependency.

- Self-host when the project needs full control over subsets, caching, and headers. Self-hosting requires storing the files and serving them from the project's own domain.
- Use a CDN only when the license is clear, the subset is available, and the extra request budget has been measured. A CDN adds a third party to the critical path.
- Prefer WOFF2 for modern browsers. Use a variable font when the design needs two or more weights from the same family.
- Record the foundry, license, and attribution URL before adding the files.
- Provide metric-compatible or near-metric-compatible fallbacks with `font-display: swap`.

See [references/fonts.md](./references/fonts.md) for the font custody checklist.

## Images

Images carry the largest payload and the highest legal risk. Handle them first.

- Prefer WebP or AVIF. Use JPEG or PNG only when the source or tooling cannot produce WebP or AVIF.
- Define the display size before generating or exporting. Do not upload a 4000 pixel image for a 1200 pixel container.
- Write alt text as content, not as metadata. Every meaningful image needs a concise description of what it shows and why it is there.
- Use `loading="lazy"` for below-the-fold images and `loading="eager"` for the largest above-the-fold image.
- If an image is generated by the `openai-image` MCP, keep the prompt, seed, and output path in the custody record. Generated images are not guaranteed to be original or free of protected trade dress; review them before they ship. Do not commit the API key.

See [references/images.md](./references/images.md) for the image format, sizing, and licensing checklist.

## Icons

Icons are small but they multiply quickly. One icon set is the default.

- Use `lucide-react` for all icons unless a custom SVG is the only option.
- Import the icon component; do not copy individual SVG files into the source unless the icon is not in the library.
- Size icons with the type and layout scales, not ad hoc pixel values.
- Do not use an icon when a text label is clearer, when the metaphor is obscure, or when the icon adds no meaning to the element.

See [references/icons.md](./references/icons.md) for the icon set, sizing, and usage rules.

## Optimization

Optimization reduces the cost an asset imposes at runtime. Use Vite-aware tooling.

- Add `vite-plugin-image-optimizer` or an equivalent to compress images at build time. Do not rely only on manual compression.
- Add a font optimizer or use subsetting to keep the font payload under the budget.
- Use responsive images with `srcset` or the framework's image component so the browser downloads the smallest usable file.
- Measure bundle impact after adding an asset. A single font family can exceed the entire JavaScript budget.

See [references/optimization.md](./references/optimization.md) for Vite plugins, compression, and bundle-size rules.

## Working rules

1. Before adding any asset, record the source, the license, the format, the fallbacks, and the date it was added. Place this record in the custody for the project, such as an asset manifest or the relevant CITATIONS.md.
2. To remove an asset, search the source tree for the file name, the import statement, the token, and the CSS reference. Remove the source file and every consumer before committing. Then run the build and the test suite to catch broken references.
3. Never add an asset without a fallback: a system font for a custom typeface, a placeholder or alt text for an image, and a text label for an icon.
4. AI-generated images are experimental. Treat them as any other image plus an additional provenance note: prompt, tool, and review status.
5. When in doubt, remove an asset. The absence of an asset rarely breaks a page; the wrong asset does.
