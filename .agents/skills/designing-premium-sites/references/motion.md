# Motion

Motion is design that moves, and good design, as *The Shape of Design* argues, is always in motion - from maker to audience and back. On the web, motion should clarify, reward, and guide. *Resilient Web Design* adds that JavaScript, the usual home of motion, is the most fragile layer. Motion must therefore be an enhancement, not a requirement, and it must respect the reader's preferences.

## Core lessons from the source

- Motion answers a question. Ask what is changing and why it matters. If the answer is only "to look nice," the animation is decoration and should probably be removed.
- One thing at a time. A page that animates everything at once feels like a distraction. Choreograph motion so it has a clear trigger and end state.
- Respect `prefers-reduced-motion`. A premium site does not assume everyone wants motion. Test and document the reduced-motion experience.
- JavaScript is the top layer. *Resilient Web Design* puts JavaScript in the fast-changing behaviour layer. Core content and navigation should not depend on JavaScript to work.
- Time tells stories. *The Shape of Design* uses time to tell stories: page layout, pacing, and scroll are narrative devices. Motion can support the story, but it should not hijack it.
- Delight is fit. *The Shape of Design* defines delight as empathy plus surprise plus clarity. Motion that fits the audience and the moment can be delightful; motion that does not is a gimmick.

## $10k vs $500

| $500 | $10k |
|---|---|
| Animations for decoration | Animations that clarify or reward attention |
| No reduced-motion support | Reduced-motion support tested and documented |
| Everything moves at once | Motion is choreographed: one thing at a time |
| Core interactions require JavaScript | Core interactions work without JavaScript; motion is an enhancement |
