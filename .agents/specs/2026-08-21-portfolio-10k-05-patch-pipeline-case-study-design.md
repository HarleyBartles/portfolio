## Approved narrative

### What Patch is for

Adventures of Patch turns agentic-engineering practice into visual stories
that people can understand, remember, present, and use.

The project is not a generic comic generator. A story earns production only
when a human presenter can state the engineering task, show the failure mode,
explain what Patch does differently, and leave the audience with a useful
action for their own workflow.

A supporting public formulation is:

> Make difficult engineering ideas memorable, then make the creative process
> repeatable without making it generic.

### The day the database disappeared

Patch began after Harley created an environment in which an agent could delete
a development database. The agent followed the affordances and authority that
Harley had engineered. The incident was therefore a systems-design failure,
not a story about an irrational agent.

The database was not business-critical. Harley rebuilt it and later rebuilt
the system more than once with improved schema and disaster-recovery planning.
He then asked the same agent to help design several layers of enforcement
around the database. Those layers became the Club DB “bouncers.”

Harley made the first deck in one day to explain:

- what happened;
- why the agent could not reasonably do otherwise inside the environment;
- why signs and instructions were insufficient; and
- how layered enforcement changed the available actions.

Patch was created as the character who could carry that explanation.

Public copy must retain Harley's accountability. Avoid “the AI deleted my
database,” “the agent went rogue,” or another formulation that assigns agency
away from the environment and authority design.

### An origin artefact, not today's quality bar

The Club DB deck is published historical evidence. It is also visibly rough:
some early text is hard to read, character continuity varies, generated-image
artefacts remain, and several visual decisions would not clear the current
pre-production and QA gates.

These weaknesses matter only if the page presents the deck as a current
production exemplar. It should instead be shown as the project origin: a fast,
useful explanation that exposed the need for a better production system.

The page should identify the shortcomings concretely and without theatrical
self-criticism. The point is not that rough work is charming. The point is
that the project learned from it and raised its acceptance standard.

### The production system is the project

A finished page or deck is one output. The broader engineering work is the
controlled route that produces it:

1. **Seed** — preserve a candidate lesson without pretending it is ready.
2. **Frame** — prove a concrete engineering task, causal failure, Patch agency,
   changed outcome, and audience action.
3. **Visual pre-production** — establish the world, cast, props, continuity,
   panel grammar, and production order.
4. **Image generation and QA** — create candidates, inspect the pixels, reject
   drift, and accept only evidence that clears the relevant lane.
5. **Deterministic compilation** — add text, layout, cards, captions, and
   licence material through reproducible builders rather than asking an image
   model to typeset the product.
6. **Published artefact and receipt** — preserve provenance, status, source
   material, transformations, and the accepted output.

The visual pipeline must be a semantic ordered composition, not six attractive
icons connected by decorative arrows. Each stage should name its input,
decision, output, and stop condition.

### Why the old adventure plans are thin

The archived adventure plans often contain nine-slide outlines, proposed
images, reusable assets, risks, and acceptance criteria. That volume does not
make them production-ready.

The failed Mission Control proof exposed the missing layer: the output placed
Patch in an attractive technology control room, where he was encouraged and
celebrated, but it did not call back to a concrete agentic-engineering task or
leave the audience with a usable practice.

An adventure passes the current frame gate only when it can answer:

1. What real engineering task is being performed?
2. What specific failure occurs?
3. What does Patch do differently?
4. What observable artefact or outcome changes?
5. What can the audience use in its own work tomorrow?
6. Does the adventure metaphor explain the mechanism rather than decorate it?

The eighteen archived concepts are raw source material. They can return only
after a successor frame passes this test.

### In visual development

#### Lawful Heist

Lawful Heist is the natural sibling to Club DB. Club DB asks how to build
several legitimate barriers around a sensitive system. Lawful Heist asks how a
properly authorised actor later gets through those barriers without creating
an invisible bypass.

The current frame follows six specialists:

- Index finds source and design-history evidence;
- Silk pressure-tests candidate routes;
- Writ establishes lawful authority;
- Klause selects a route under constraints;
- Rollback supplies recovery and containment; and
- Receipt preserves an auditable record.

The smooth heist is deliberately anticlimactic: Patch scans a correctly
programmed override credential and the vault opens. The planning did the work.

At the observed evidence state, all six specialists have approved hero, style,
and anti-pattern sheets. A continuity-object sequence also exists. Patch's
comic adaptation, the final vault/keycard system, safehouse environments,
body-slide art, and final deck plan remain incomplete. Public status:
**advanced visual pre-production; not deck-ready**.

#### Tournament of Reasonable Defaults

Tournament teaches:

> Stakeholder analysis and consultation prevents false deliverables.

Patch does not refuse a thin ticket. He maps decision owners, asks targeted
questions, turns the ticket into an executable event card, runs the defined
race, and reaches an acceptance condition owned by the appropriate judges.
Bit and Bot move quickly but produce plausible false deliverables because they
run before consultation.

The repository contains accepted or reported-complete character, stakeholder,
environment, official, prop, and setup-image packages. The live planning state
still requires a revised deck plan, revised body-image plan, accepted scene
art, PPTX, sidecar, QA, and receipts. Public status: **visual pre-production
ready for revised scene planning; not a finished deck**.

#### Identity Emporium

Identity Emporium teaches:

> A costume is not an identity.

A useful agent identity binds name, role, domain, doctrine, playbooks, methods,
tools, source grounding, boundaries, and definition of done. The story contrasts
task attempt with task completion through Patch, Bit, and Bot working across
the Emporium and concrete task domains.

The project has an accepted Patch-in-world proof and repo-resident references
for the Emporium overview, exterior, interior, world proof, and shopkeeper.
The current manifests classify those packages as legacy references rather
than production-ready canon. Public status: **substantial visual exploration;
not asset-ready or deck-ready**.

### Inside the story lab

The story lab communicates breadth without turning private planning into a
public backlog.

Seven current fairytale seeds have concise operational lessons:

- preserve escalation signal;
- agreement is not evidence;
- leave purposeful recovery breadcrumbs;
- build resilience before predictable pressure;
- let temporary authority expire;
- verify identity, provenance, and authority; and
- distinguish technical capability from authorisation.

They may appear as a compact typographic ledger. They receive no release dates,
progress bars, GitHub placeholders, or disabled controls.

Only four archived adventure directions currently pass the public future-work
litmus test in extracted form:

- **Test Goblin** — turn failure-mode suspicion into ranked, executable test
  scenarios;
- **The Tiny Change That Wasn't** — map references, consumers, tests,
  migrations, documentation, and operations before treating diff size as
  blast radius;
- **Review Dragon** — shape completed work into a reviewer handoff containing
  intent, risk, evidence, gaps, and requested attention; and
- **Hall of Mirrors** — separate observation, inference, assumption,
  contradiction, and uncertainty before proposing a bounded hypothesis and
  next check.

These are credible questions under consideration. The page must not imply that
their archived slide plans have been approved unchanged.

### Public proof and private workshop

GitHub proves landed public assets, manifests, source, and published outputs.
It is not the perimeter of Harley's work or thinking.

Linear is Harley's private planning and sequencing surface. It may be named as
part of the production system, alongside his practical experience of Jira,
Azure DevOps, and GitHub, but private Linear content must not be published.

Use this public formulation in substance:

> The public repository shows what has earned a durable artefact. Earlier
> planning and future directions do not all begin—or remain—in public.

An optional supporting line is:

> I use Linear to shape and sequence work, GitHub to prove what has landed,
> and the published catalogue to mark what is ready for an audience.

The absence of a link on a future-work entry is intentional. Do not render a
disabled button, empty URL, or “coming soon” control.

Show Club DB, Goldilocks, The Sorcerer's Apprentice, and the finished

### 6. In visual development — `Three worlds in motion`

Give Lawful Heist, Tournament, and Identity Emporium distinct editorial
profiles. Each profile contains:

- the lesson;
- the visual mechanism;
- the strongest current evidence;
- the exact status;
- what remains; and
- a public repository link only where the evidence is public and stable.

### 7. Story lab — `What Patch might teach next`

Use a compact typographic composition for the seven fairytale lessons and four

section should feel like an editorial notebook, not a backlog board.

### 8. Public proof — `The repository is evidence, not the whole workshop`

Explain the GitHub/Linear boundary, source custody, and the role of manifests
and sidecars. Name Linear without exposing it.

### 9. Close — `Controlled creative production`

Return to the senior claim: generative imagery is not the achievement. The
achievement is placing creative generation inside a system of framing,
custody, QA, human judgement, deterministic compilation, and honest
publication.

End with the public repository and published-work routes.

## Visual and interaction contract

This route should be replete with Patch imagery. Patch is the project signature
and may recur through the hero, origin, pipeline, section turns, and closing
beat.

Every appearance must still have a job. Suitable roles include:

- introducing the project;
- inspecting the origin failure;
- explaining a production gate;
- reviewing or rejecting a candidate;
- assembling a deterministic artefact;
- presenting accepted work; and
- sketching future lessons.

Avoid decorative repetition, random mascot stickers, identical poses, and
images that merely fill empty space. Patch can be abundant without becoming
wallpaper.

### New Patch image generation

The implementation may generate composition-specific Patch poses when existing
assets cannot carry a section's meaning. This is approved scope, not a mandate
to reach an image quota.

New Patch imagery must:

1. originate under Adventures of Patch custody rather than being created as an
   undocumented portfolio-only derivative;
2. use the current Patch style bible, approved positive references, and
   negative or anti-pattern sheets;
3. preserve Patch's whole-character identity before adding scene detail;
4. use generated art for Patch, pose, props, and environment only;
5. keep all explanatory text, labels, diagrams, and captions in deterministic
   HTML or build tooling;
6. receive pixel-level image QA and an explicit acceptance state;
7. be visually accepted by Harley before portfolio publication;
8. retain the generation prompt and sidecar provenance;
9. be compiled into an appropriate asset family or explicitly classified as a
   portfolio-specific accepted source; and
10. enter the portfolio only after the accepted Adventures source and exact
    revision are known.

Canonical Patch details include the teal long-sleeved hoodie with hood up,
off-white unbordered face panel, two dark-tipped antennae, simple black oval
eyes, dark trousers, teal shoes, and crossbody bag with attached dark strap and
white greater-than mark. Prompting should use the current whole-character lock,
not reconstruct Patch casually from this abbreviated list.

Generate separate wide and narrow compositions when a crop would damage the
pose or evidence. Do not stretch, mirror, or silently edit an accepted Patch
asset into a state that has not been QA'd.

### Art direction

Retain the portfolio's premium editorial field-journal system while allowing
Patch's warm cream, teal, ink, and rounded illustration language to occupy more
space than it does elsewhere on the site.

- Use Patch artwork as editorial illustration inside the portfolio, not as a
  competing microsite theme.
- Let accepted adventure-world art introduce controlled visual changes for
  Heist, Tournament, and Identity Emporium.
- Treat Club DB as archival material rather than applying a fake distressed
  filter.
- Keep future work typographic where no accepted production image exists.
- Use status labels and captions near the evidence they qualify.
- Avoid comic-book display type, speech bubbles for body copy, faux paper
  textures, dashboard cards, fake progress meters, and autoplaying carousels.

Version one is static. Small hover, focus, or entrance transitions may support
hierarchy, but no required content is hidden and reduced motion changes no

### Accessibility

Patch images need concise alt text describing the action relevant to the
section, not a repeated full character description. Decorative recurrences may
use empty alt text only when adjacent text carries the complete meaning.

Every evidence image needs a visible caption explaining what it proves and
what status it has. Do not transcribe an entire slide, style sheet, or one-page
poster into alt text. Repeat essential lessons and labels as selectable HTML.

The pipeline uses an ordered list in source order. Status cannot depend on
colour. At 200% zoom, readers must still understand the distinction between
published, visual development, and story seed without enlarging raster text.
